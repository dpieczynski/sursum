# 0014 — Rust frontend: Leptos 0.8 CSR with Trunk, WebDriver tests

Status: Accepted (2026-11-16). Supersedes the original plan decision 4 (TypeScript, Svelte 5,
Vite) and the use of ts-rs.

## Context
The original plan had a Rust server and a TypeScript/Svelte frontend with types generated by
ts-rs. The project owner prefers a single language and toolchain without Node/npm.

## Decision
- The **screen** and the **remote** are Leptos **0.8** apps in client-side rendering (CSR) mode,
  compiled to WebAssembly with **Trunk** (0.22). Leptos 0.9 is only at rc1, so we stay on 0.8.
  cargo-leptos is not used: it targets SSR/hydration with a Leptos server, while our server is
  our own axum app; the Leptos book recommends Trunk for CSR with an existing server.
- Shared crates:
  - `sursum-protocol`: serde types for server and clients (data only; native + wasm32). Replaces
    ts-rs; no code generation.
  - `sursum-slide`: the slide component (`Stage`, `SlideView`, `LayeredStage`, `Masks`,
    `fit_deck`) for the screen and the remote preview.
  - `sursum-client`: WebSocket client (reconnect, heartbeat) and signal-based store, used by both
    apps (avoids duplicating reconnect logic or putting it into the rendering crate).
- i18n with `leptos_i18n` 0.6 (compile-time checked keys; requires leptos ^0.8).
- JSON over WebSocket (`serde_json` on both sides); `insta` snapshots guard the wire format.
- Screen/remote end-to-end tests use **WebDriver from Rust with thirtyfour** (0.38, `cdp` and
  `bidi` features) and `chromium-driver`. Playwright for Python is the fallback for cases
  WebDriver + CDP/BiDi cannot cover. fantoccini was considered (solid, lower level, no built-in CDP).
- **Dioxus is not used.** A native remote app is not justified: wake lock is solved by device
  settings (later HTTPS, ADR 0007), the remote is used in the foreground, pedals are keyboards
  the browser handles. A native app would add APK signing/distribution (incl. developer
  verification for sideloading) and, crucially, break the shared slide component (Dioxus has its
  own component model). If a native shell is ever needed, prefer a thin Android WebView wrapper
  around the same Leptos remote.

## Consequences
- One language and toolchain (rustup, cargo, Trunk); no Node, npm, TypeScript or Python in the
  devcontainer; `cargo about` and `cargo deny` cover all dependencies.
- Domain logic still lives only on the server: shared wasm crates share data and drawing, never
  logic.
- New risks: Leptos is pre-1.0 (pin 0.8.x, keep Leptos code confined to `sursum-slide`,
  `sursum-client` and `apps/*`); WASM size and startup time must be measured (release profile
  with `opt-level = "z"`, LTO, `wasm-opt`, CI size check); `wasm-bindgen-cli` must match the
  `wasm-bindgen` crate version; browser APIs are called through `web-sys` (more verbose).
- Clippy runs for both native and `wasm32-unknown-unknown`; `leptosfmt` formats `view!` macros.
- ADR 0010 is amended: license metadata lives only in Cargo manifests.
